## Facts established on the sandbox (Redis 8.10.2)

- `TYPE` returns `vectorset` (encoding `raw`) and `array` (encoding `sliced-array`).
- Vector sets: `VCARD`, `VDIM`, `VINFO`, `VRANGE key start end count` (lexicographic member paging, `-`/`+` and
  `[`/`(` bounds), `VGETATTR`, `VEMB [RAW]`, `VLINKS [WITHSCORES]`, `VISMEMBER`, `VRANDMEMBER`, `VSIM` (by `ELE` or
  `VALUES`/`FP32`, `COUNT`, `EF`, `FILTER`, `WITHSCORES`, `WITHATTRIBS`), writes `VADD`, `VREM`, `VSETATTR`.
- Arrays are sparse and index-addressed: `ARLEN` is max index + 1, `ARCOUNT` the number of set elements, `ARINFO`
  metadata (`count`, `len`, `next-insert-index`, slices). Reads: `ARGET`, `ARMGET`, `ARGETRANGE`, `ARSCAN key start end
  [LIMIT n]` (index-value pairs of existing elements), `ARGREP` (EXACT/MATCH/GLOB/RE predicates, `LIMIT`,
  `WITHVALUES`), `AROP` (SUM/MIN/MAX/AND/OR/XOR/MATCH/USED over a range), `ARLASTITEMS`, `ARNEXT`. Writes: `ARSET`,
  `ARMSET`, `ARINSERT`, `ARRING`, `ARSEEK`, `ARDEL`, `ARDELRANGE`. ACL category `@array` plus `@read`/`@write`.
- No graph module is loaded. FalkorDB (the maintained successor of RedisGraph, `GRAPH.*` commands) is added as an
  optional sandbox service for S4.

## Requirements common to every stream

- Hard rules in `AGENTS.md` section 2 hold without exception: values travel as `Bin` and render as text; every Redis
  read is bounded (count, bytes, time) and data-dependent replies use the measured transport; edits that replace data
  use compare-and-set; destructive operations get a server-built confirmation; the policy fails closed; viewers never
  get write controls; read-only and prod rules apply.
- Policy: every new command family gets explicit rules (module flags are not trusted alone). Removing data
  (`VREM`, `ARDEL`, `ARDELRANGE`, `GRAPH.DELETE`, Cypher that writes) asks for confirmation the way the existing
  equivalents do; nothing new is admin-only unless its blast radius is the whole key or more.
- Contract changes are additive and logged in `docs/CONTRACT-CHANGES.md`; new routes go into `ROUTES` and the e2e role
  matrix; new test ids into `apps/web/TESTIDS.md`; behaviour into `docs/USER-GUIDE.md` and bounds into
  `docs/ARCHITECTURE.md`.
- Tests: unit and integration (against `sandbox-e2e`, keys under your own prefix, deleted afterwards), e2e specs for
  each role, and live QA in Chromium as viewer, operator and admin with 0 CSP/Trusted Types violations and 0 page
  errors, recorded in `docs/qa/v04-<stream>.md`.
- The repository is public: committed files contain sandbox data only, no absolute local paths, host names or
  details of anyone's machine.
