# v0.2 plan

`v0.1` (git tag) is the restore point the owner tested. All v0.2 work lands on branch `release/v0.2`, then `main`, tagged `v0.2`.

## Goals (from the owner)
1. **UI/UX upgrade.** The v0.1 UI is clean but generic: large empty areas, identical cards with no information, low density for a developer tool. It must feel like a purpose-built instrument for Redis, not an admin template.
2. **Development data.** Two new databases (done, see below).
3. **Smart console.** Industry-standard keyboard shortcuts and visual cues; make users fast and confident, and make the console recognisable to anyone who has used redis-cli, a terminal, VS Code or a database IDE.
4. **Review loops.** Whole-site code review by several models; verify each finding against current code; fix only still-valid issues (minimal changes), skip the rest with a reason; validate; repeat until clean.
5. **Live testing is mandatory.** Every feature is tested by actually using the site in a browser, as every role, on real data. No test case is skipped, skimmed, or assumed from reading code.

## Design direction (UI agent finalises it in `docs/DESIGN.md` before coding)
- **Subject.** A Redis keyspace: colon-delimited namespaces of typed keys, each with a TTL that burns down. Audience: backend developers (Spring/Node) debugging their app's cache, sessions and queues, plus admins. Primary job: find a key fast, understand it, change it safely, on the right database.
- **Shape.** An instrument/IDE workspace, not a card dashboard: collapsible icon rail; namespace tree + key list; inspector pane; a persistent status bar (connection, server version, role, environment, key count, latency). Dense, left-aligned, data at ~13px.
- **Environment is unmistakable.** Staging/prod (and read-only) mark the whole frame persistently, not just a badge.
- **One signature element:** "key anatomy" — key names rendered as namespace segments with dimmed delimiters and distinguished IDs/UUIDs/numbers, plus a TTL fuse that visibly burns down. Used consistently in the list, inspector, console results and confirmations. Keep everything else quiet.
- **Type colours.** One consistent hue per Redis type (string, hash, list, set, zset, stream, JSON, timeseries, …) used everywhere (list glyphs, inspector, console highlighting).
- **Fonts** self-hosted (CSP `font-src 'self'`), at most two families, chosen for identifier legibility (l/1/I, O/0 disambiguation; slashed or dotted zero in the mono). OFL/Apache licences only.
- **Avoid template tells:** identical rounded cards with soft shadows, gradient washes, all-caps eyebrow labels, accenting one word in a heading, near-black #111 backgrounds with one neon accent, cream + terracotta.
- **Database landing** shows real information per database (status, version, keys, memory, ops/s, environment, role, read-only), last-used first, keyboard-openable.
- Quality floor: light + dark, 1280–1920 widths (usable at 1024), visible focus, reduced motion respected, WCAG AA contrast, zero CSP violations.

## Console direction (console agent)
Benchmarks: redis-cli, iredis, Chrome DevTools console, VS Code / Warp terminals, psql, DataGrip/TablePlus, Redis Insight Workbench. Cover at least:
- Keys: Enter run; Shift+Enter newline; ↑/↓ history (only at first/last line); Ctrl+R reverse history search; Tab / → accept completion; Ctrl+Space open completion; Esc dismiss/clear; Ctrl+L clear screen; Ctrl+C clear the line or cancel a running command; Alt/Option+↑/↓ move between result blocks; Cmd/Ctrl+Shift+C copy last result; F1 or Cmd/Ctrl+/ docs for the current command; `?` (outside inputs) shortcut overlay. Respect the global Cmd/Ctrl+K palette. Mac vs Windows/Linux labels.
- Cues: prompt shows database, environment colour and role; syntax highlighting by argument role (command, subcommand, key, value, number, flag) using COMMAND DOCS; ghost-text suggestion from history; signature hint with the current argument highlighted; live policy badge (read / write / admin / confirm / blocked + reason) and a danger state for destructive commands before running; running state with elapsed time and cancel; result blocks with status gutter, duration, size, collapse, copy, re-run; key names in results open the key browser; "did you mean" for unknown commands; KEYS→SCAN guidance.
- Workbench: Cmd/Ctrl+Enter run all, Shift+Enter run line/selection, per-line gutter status and policy markers.
- Every shortcut has a visible UI equivalent and is listed in the overlay; shortcuts never fire while typing in unrelated inputs; aria-live announcements for results.

## Review loop (after the two feature branches merge)
Each round: independent reviewers (different models from the authors) review the whole site — code and a live browser session as every role — and write findings with evidence. A fixer verifies every finding against the current code, fixes only still-valid ones with minimal changes and a regression test, and records skipped ones with a reason in `docs/REVIEW-LOG.md`. Then all suites run (typecheck, server, web, full E2E) plus a live smoke tour. Repeat until a round produces no valid Medium+ findings.
