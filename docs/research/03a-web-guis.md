# Self-hosted web Redis GUIs: research shortlist

Researched 2026-10-22. Web research only: repository pages, public GitHub REST metadata, documentation, source files, and published advisories. Nothing was cloned, installed, built, or run. This is a source/documentation assessment, not a penetration test or live compatibility qualification.

## Top 3, ranked for this brief

1. **[Zedis Web](https://github.com/vicanso/zedis)** — closest documented match: backend-held encrypted credentials, web terminal with completion/help, server-enforced read-only roles and server restrictions, and SSO through a trusted authenticating proxy. Rust rather than Node. Its web distribution is explicitly an early preview; confirm the chosen release contains the documented controls. [Web deployment/security guide](https://github.com/vicanso/zedis/blob/main/docs/WEB.md)
2. **[LibreDB Studio](https://github.com/libredb/libredb-studio)** — strongest Node/TypeScript fit: native OIDC, role-filtered managed connections with server-only secrets, and a Redis command editor. Use managed seeds and disable custom connections. Four recent authentication/session isolation advisories make release selection and independent review essential; the latest listed patch floor is **1.0.0**. [Managed connection API](https://github.com/libredb/libredb-studio/blob/02dc26057f373fe920cfb4908c8dcd6aae7ba720/src/app/api/connections/managed/route.ts), [advisories](https://github.com/libredb/libredb-studio/security/advisories)
3. **[RESPdeck](https://github.com/aeke/respdeck)** — promising small TypeScript base with verified Redis TLS, encrypted saved passwords, CSRF protection and API-enforced read-only connections. A substantial partial fit: one administrator session, no native SSO/multi-user RBAC, and **no arbitrary command console**. Choose as a foundation to extend, not a complete smart redis-cli replacement. [Security and data behavior](https://github.com/aeke/respdeck#security-and-data-behavior)

These are evaluation priorities, not production security approvals. No candidate was demonstrated live to satisfy every requirement.

## Functional and security comparison

**Types:** “core-5” = string, hash, list, set, sorted set; “core-6” adds streams. These mean documented/rendered types, not a claim that every operation works. Arbitrary CLI dispatch can address additional types without offering a dedicated editor.

**Credentials:** “yes” means a documented server configuration or managed backend store can keep Redis secrets away from ordinary browser users. Initial setup by an administrator may still use a browser. “Partial/unverified” is deliberately not a pass. Encrypting disk storage alone does not establish this property.

- [GHSA-78jw-7pvp-64h3](https://github.com/libredb/libredb-studio/security/advisories/GHSA-78jw-7pvp-64h3): moderate, signed-in users can disconnect others' connections; affected ≤0.18.3, fixed **1.0.0**.

For a LibreDB evaluation, use **managed: true** seeds, `ALLOW_CUSTOM_CONNECTIONS=false`, and role-filtered server configuration. The inspected pinned [managed API](https://github.com/libredb/libredb-studio/blob/02dc26057f373fe920cfb4908c8dcd6aae7ba720/src/app/api/connections/managed/route.ts) strips secrets only for managed connections; editable ones can carry them. The pinned [custom-connection policy](https://github.com/libredb/libredb-studio/blob/02dc26057f373fe920cfb4908c8dcd6aae7ba720/src/lib/config/custom-connections.ts) documents server-side enforcement. Current [Redis provider docs](https://github.com/libredb/libredb-studio/blob/main/docs/providers/redis.md#43-ssl--tls) say `ssl.mode=require` sets `rejectUnauthorized:false`; choose a verifying mode and required CA settings. An older Redis tools-directory description says TLS is unsupported; current repository docs supersede that description for this report, but the selected release must be checked.

For Zedis, review the distinction between trusted-proxy identity and local bridge roles. Server restrictions should use stable entry IDs when renaming could change name-based matches. Audit coverage is configurable, not automatically every read/command, and some current guide features require a post-v0.14.0/nightly build. [Web guide](https://github.com/vicanso/zedis/blob/main/docs/WEB.md)

RESPdeck's first public release candidate supports standalone Redis only; Cluster, Sentinel, RedisJSON and multi-user access are roadmap items. Its one-admin-session model is particularly restrictive for a shared developer service. [Release scope](https://github.com/aeke/respdeck#respdeck)

## Practical conclusion

Start a release-pinned security/UX evaluation with **Zedis Web and LibreDB Studio**. Keep **RESPdeck** as the narrower TypeScript foundation option. For every option, the decisive follow-up is evidence that ordinary browser sessions receive no Redis secrets, cannot change connection destinations, and cannot bypass read-only/server scopes through direct API calls or the command console. Redis ACLs must enforce the intended command/key scope independently; a login page or a client-side confirmation dialog does not provide that boundary.
